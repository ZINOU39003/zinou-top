# ZINOU TOP update system

## Flow

```
GitHub Release (published, tag vX.Y.Z)
  └─ update.json  ──(1) preflight: HTTPS fetch + strict validation          ZinouUpdateManager.preflight
        └─(2) engine: compare versionCode with the installed app           AppUpdateChecker (upstream)
              └─(3) pick download list for the device ABI                   downloadUrlList_<abi> → downloadUrlList
                    └─(4) download APK over HTTPS                           AppDownloader (upstream)
                          └─(5) verify before install                       ZinouUpdateManager.verifyAndInstall
                                SHA-256 + size == update.json
                                package == com.zinou.top
                                versionCode > installed and == latest in update.json
                                └─(6) Android Package Installer (user confirms; Android checks the signature)
```

The upstream SmartTube update engine is reused (it is mature: versionCode comparison, ABI choice, download,
installer intent). ZINOU wraps it in the `zinou` flavor only:

| Hook (in `AppUpdatePresenter`) | Purpose |
|---|---|
| `start()` → `ZinouUpdateManager.preflight()` | fetch/validate `update.json` first; handles not configured / no internet / no release / invalid data |
| `onUpdateError()` → `handleEngineError()` | friendly message for download failures |
| `installUpdate()` → `verifyAndInstall()` | SHA-256 and package/version gate before the installer |

Upstream flavors are not affected (`R.bool.zinou_branding` is false there).

## Configuration

Only [`zinou.properties`](../zinou.properties):

```properties
github.owner=YOUR_USERNAME
github.repository=zinou-top
```

`common/zinou-config.gradle` turns it into `BuildConfig` constants exposed by
`com.liskovsoft.smartyoutubetv2.common.zinou.ZinouUpdateConfig`:

| Constant | Value |
|---|---|
| `GITHUB_OWNER`, `GITHUB_REPOSITORY` | from `zinou.properties` |
| `UPDATE_MANIFEST_URL` | `https://github.com/<owner>/<repo>/releases/latest/download/update.json` |
| `RELEASE_API_URL` | `https://api.github.com/repos/<owner>/<repo>/releases/latest` |
| `GITHUB_URL` | `https://github.com/<owner>/<repo>` (About → GitHub, shown only when configured) |
| `ALLOWED_DOWNLOAD_HOSTS` | `github.com` |

While the owner is `YOUR_USERNAME`, all URLs are empty: the app ships no placeholder URL and
"Check for updates" says the update source is not configured.

`update.json` is used instead of the GitHub REST API: it needs no API rate limit (60 requests/hour per IP for
anonymous API calls, often shared by many TVs behind one router), carries the SHA-256 values, and is exactly the
format the upstream engine reads.

## update.json

Generated by `scripts/release/make_release_assets.py` — never edit by hand.

```json
{
  "package": {
    "downloadUrlList": ["https://github.com/OWNER/zinou-top/releases/download/v1.0.1/ZinouTop-v1.0.1.apk"],
    "downloadUrlList_armeabi-v7a": [".../ZinouTop-v1.0.1-armeabi-v7a.apk", ".../ZinouTop-v1.0.1.apk"],
    "downloadUrlList_arm64-v8a":   [".../ZinouTop-v1.0.1-arm64-v8a.apk",   ".../ZinouTop-v1.0.1.apk"],
    "downloadUrlList_x86":         [".../ZinouTop-v1.0.1-x86.apk",         ".../ZinouTop-v1.0.1.apk"],
    "sha256": { "ZinouTop-v1.0.1.apk": "<64 hex>", "ZinouTop-v1.0.1-arm64-v8a.apk": "<64 hex>", "...": "..." },
    "size":   { "ZinouTop-v1.0.1.apk": 31457280, "...": 0 }
  },
  "1.0.1": { "versionCode": 10001, "changelog": ["..."], "changelog_ar": ["..."] },
  "1.0.0": { "versionCode": 10000, "changelog": ["..."] }
}
```

- The device's primary ABI selects `downloadUrlList_<abi>`; the universal APK is the fallback (e.g. `x86_64`).
- APK URLs point to the **versioned tag** (`/download/v1.0.1/`), so the files always match the hashes.
- Validation rules (identical in Java `ZinouUpdateManifest` and Python `validate_update_json`):
  `package` object required; every other key is a version with integer `versionCode > 0`; every URL is
  `https://github.com/...*.apk` without query/fragment; every APK has a 64-hex SHA-256; sizes (if present) are positive;
  maximum 256 KB.

## Messages and error handling

| Situation | Behaviour |
|---|---|
| Manual check started | "Checking for updates…" + loading indicator |
| Up to date | "You're using the latest version" |
| Update available | dialog / sidebar entry "ZINOU TOP X.Y.Z" with changelog and **Install update** |
| No internet, DNS, timeout (15 s connect / 20 s read), TLS error, GitHub 5xx | "Unable to check for updates right now." / «لا يمكن التحقق من وجود تحديث حاليًا.» |
| No published release (`update.json` 404) | "No published ZINOU TOP release was found." |
| Malformed / unsafe `update.json`, redirect to HTTP | "The update information is invalid. The update was cancelled." |
| Download failed / interrupted | "The update could not be downloaded. Please try again later." |
| SHA-256 / size / package mismatch | "Update verification failed (SHA-256)…" — file deleted, nothing installed |
| Downloaded version not newer | "…not newer than the installed one. Nothing was installed." |
| Owner not configured | "The update source is not configured in this build." |

Automatic checks (About → *Notify about updates*: Disabled / Sidebar notification / Dialog) never show errors and
never install anything without the user.

## Security notes

- HTTPS only; OkHttp is configured not to follow HTTPS→HTTP redirects.
- The SHA-256 values come from the same GitHub release as the APK. They protect against corrupted, truncated or
  swapped downloads and mismatched assets. The **final** authority is Android: an update installs only if it is signed
  with the same key as the installed app. Keeping the release key private is therefore essential (SIGNING.md).
- Known limitation: the upstream downloader reports progress only as a loading indicator (no percentage).
